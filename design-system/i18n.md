# i18n

Dashboards are multi-language. **en**, **pt-PT**, **es**. Default locale is **pt-PT**.

Runtime: `src/main/resources/admin/i18n.js`  
Catalogs: `admin/catalog.en.js`, `catalog.pt.js`, `catalog.es.js`

## Resolution order

1. `localStorage.uiLocale` (user picked a language)
2. Tenant default via `I18N.applyTenantDefault(tenant.locale)`
3. `navigator.language`
4. `pt-PT`

## Namespaces

| Prefix | Surface |
|---|---|
| `common.*` | Shared (nav labels, language switcher) |
| `app.*` | Tenant dashboard `/app` |
| `admin.*` | CRM copy used inside `/app` (clients, quotes, invoices, catalog) |
| `backoffice.*` | Platform `/backoffice` |

## Adding a string

1. Add the same key to **all three** catalogs.
2. Keep keys stable; do not reuse a key for different meaning.
3. Static HTML: `data-i18n="admin.nav.clientes"` (textContent), `data-i18n-placeholder`, `data-i18n-aria-label`, `data-i18n-title`.
4. JS: `const STR = I18N.section('app');` then `STR.loginTitle`. Nested keys after the section prefix are one level in the proxy (`STR.loginTitle` → `app.loginTitle`). Deeper trees in catalogs are objects; use `I18N.t('admin.login.title')` or a nested section if the file already does that.
5. Interpolation: catalog value `'Hello {name}'` + `I18N.t('app.hello', { name })`.
6. Dynamic copy: catalog function, e.g. `igFailed: reason => \`…${reason}\``.
7. After swapping locale, call `I18N.applyDom(document)` so static chrome updates; re-render JS views; call `window.refreshThemeLabels()` so the theme button uses `common.themeToLight` / `common.themeToDark`.

## Rules

- No user-facing literals in HTML or JS render functions. That includes buttons, empty states, toasts, drawer titles, validation, placeholders, aria-labels, and “coming soon”.
- Brand marks (`AI`, `BO`, `CRM`) and numeric/currency formatting may stay in code. Currency uses `Intl.NumberFormat`; prefer the tenant locale/timezone when the module already does.
- When editing a function that already has hardcoded copy, lift those strings into the catalogs in the same change.
- Do not add a fourth catalog format (JSON files, inline maps) for dashboard UI.

## HTML example

```html
<button class="btn btn--ghost" id="btn-logout" data-i18n="app.logout">Log out</button>
<input class="inp" data-i18n-placeholder="app.searchPlaceholder" placeholder="Search…" />
```

Fallback text in the HTML is for first paint / no-JS; catalogs still own the key.

## JS example

```js
const STR = I18N.section('app');
toast(STR.loginInvalid);
```
